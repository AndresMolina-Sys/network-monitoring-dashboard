# Fase `change`

Lee la spec existente, plan y tareas relacionados, `docs/constitution.md` y decisiones confirmadas por el usuario. Actualiza únicamente `spec.md` para reflejar el cambio y sus efectos en RF, casos límite, aceptación y fuera de alcance. Conserva el qué/porqué; no cambies código ni reescribas automáticamente plan o tareas.

Deja la spec `Pendiente de aprobación` y resume qué decisiones o secciones del plan/tareas quedan potencialmente obsoletas. El coordinador ejecuta QA de spec automáticamente antes de presentar el resultado y espera aprobación explícita; las fases plan/tasks revisarán después sus propios artefactos.
